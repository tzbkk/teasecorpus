# teasecorpus

A Chinese ChatML SFT dataset generated from the [「擅长捉弄的高木同学」Fandom wiki](https://karakai-jouzu-no-takagi-san.fandom.com/zh/), with record-level contributor provenance tracked by [originblame](https://github.com/tzbkk/rust-originblame).

## Dataset Description

- **Homepage:** https://karakai-jouzu-no-takagi-san.fandom.com/zh/
- **Repository:** https://github.com/tzbkk/teasecorpus
- **Space:** https://huggingface.co/spaces/tzbkk/teasecorpus-ob (provenance explorer)
- **Point of Contact:** Haolin Xue \<tzbkk@outlook.com\>
- **License:** CC-BY-SA-3.0 (inherited from Fandom wiki)

**Summary:** 1,410 question-answer pairs in ChatML format, covering 7 content types (chapters, characters, episodes, music, volumes, seasons, movies). Each record is traceable to its source wiki page and all contributors who edited that page, via originblame — a record-level provenance system. If a contributor requests content removal, their derived QA can be surgically revoked without deleting the entire dataset.

## Dataset Structure

### Data Instances

Each line in `train.jsonl` is a JSON object with a single `messages` array:

```json
{
  "messages": [
    {
      "role": "system",
      "content": "你是一个基于给定资料回答问题的助手。严格依据提供的字段文本作答,不推测、不编造。所有问题自包含,不依赖上下文代词。"
    },
    {
      "role": "user",
      "content": "原高木漫画第52章的发布日期是?"
    },
    {
      "role": "assistant",
      "content": "2018年8月8日"
    }
  ]
}
```

### Data Fields

| Field | Type | Description |
|-------|------|-------------|
| `messages` | list[{role, content}] | ChatML conversation. Always 3 turns: system → user → assistant. |
| `messages[].role` | string | One of `system`, `user`, `assistant`. |
| `messages[].content` | string | Message text (Chinese). |

### Data Splits

| Split | Num examples |
|-------|-------------|
| `train` | 1,410 |

No validation/test split — this is a training-only dataset.

## Dataset Creation

### Curation Rationale

This dataset demonstrates that SFT data generated from collaborative content (e.g., Fandom wikis) can preserve contributor-level attribution at the record level. Unlike typical wiki-derived datasets that treat source content as a monolithic corpus, every QA pair here is linked to the specific wiki page and all editors of that page through [originblame](https://github.com/tzbkk/rust-originblame).

### Source Data

#### Pipeline

This dataset was generated by the [teasecorpus](https://github.com/tzbkk/teasecorpus) pipeline — an end-to-end toolkit for producing SFT datasets from Fandom wikis with contributor provenance. The pipeline handles: wiki dump ingestion, structured parsing, QA generation (LLM + template), and originblame provenance registration. It is designed to be reproducible: re-running the pipeline on the same wiki dump yields the same dataset.

#### Initial Data Collection

Wiki pages were fetched via the Fandom API as XML dumps. The source wiki contains:

- **408 main namespace (ns0) pages** — chapter summaries, character profiles, episode guides, music releases, volume listings, etc.
- **23 unique contributors** (21 registered users + 2 anonymous IPs)
- **License:** CC-BY-SA-3.0

#### QA Generation

Questions and answers were generated by two methods:

1. **LLM-generated** (1,295 records): [DeepSeek](https://www.deepseek.com/) V4-flash, temperature 0.5, with an anti-tautology system prompt and post-generation filtering to reject trivial Q/A pairs.
2. **Template-generated** (115 records): Deterministic templates for structured data (volume metadata, music track listings).

All records share a single system prompt enforcing grounded, speculation-free responses.

### Provenance

Provenance metadata is tracked by [originblame](https://github.com/tzbkk/rust-originblame) and stored alongside the dataset:

- **409 sections** registered (408 wiki pages + 1 translation table). Each section stores: `{path (page title), authors (SHA-256 ID list), license, year}`.
- **23 authors** registered with name + obfuscated email.
- Each of the 1,410 QA records is linked to its source section(s) via `ob blame`.

**Querying provenance:**

```bash
# Find which wiki page + contributors produced a given record
ob blame output/dataset.jsonl 1

# Find all records derived from a specific contributor
ob show --author "铁桶"
```

If a contributor requests content removal (e.g., right-to-be-forgotten), `ob revoke --author <name>` surgically revokes their derived records without affecting other contributors' content.

> **Note:** The `messages` JSON itself does not contain provenance fields. Provenance is stored externally in `.ob/` and queried through the `ob` CLI. This keeps the training data clean for standard SFT pipelines while preserving full traceability.

## Considerations for Using the Data

### Discussion of Biases

- **Fandom bias:** Wiki content reflects fan community interpretations, which may differ from canonical source material (manga/anime).
- **LLM generation bias:** Questions are biased toward factual recall (dates, names, plot points) rather than open-ended reasoning. The anti-tautology filter skews toward non-trivial but verifiable answers.
- **Contributor bias:** 23 contributors with uneven edit distribution — a small number of power users contributed the majority of source content.
- **Language coverage:** All content is in Chinese (Simplified). No multilingual coverage.

### Other Known Limitations

- **Scale:** 1,410 records is small for production SFT. Intended as a provenance demonstration, not a benchmark-scale dataset.
- **Static snapshot:** Content reflects the wiki state at dump collection time. Wiki edits after collection are not captured.
- **No human verification:** QA pairs are LLM/template-generated and not human-validated. Factual errors from the source wiki may propagate.
- **Single-domain:** Only covers one anime/manga franchise. Generalization to other domains is not tested.
